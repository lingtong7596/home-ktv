# 家庭 KTV 部署手册（v1.2.0）

> 三端架构：**NAS（fpk 服务）** ← 局域网 → **投影仪（APK）** + **手机（微信扫码 H5）**
> 本手册按 `192.168.1.100:9188` 编写，实际 IP 以你的 NAS 为准。

---

## 〇·一、v1.1.1 追加改动（第二轮 UI 意见）

投影仪 APK 点歌台按手绘稿重做：

- **三栏布局**：左=歌曲列表（序号红/歌名白/歌手青/类型蓝/语种粉，对应手绘稿分色），中=字母+数字索引大按钮（A-E/F-J/K-O/P-T/U-Y/Z/0-9/全），右=点歌二维码 + 快捷键说明；**大类（歌名/歌星/排行/收藏/已点）移到底部**
- **三道杠键在点歌台内=依次切换大类**（歌名→歌星→排行→收藏→已点），在播放页仍是已点面板开关
- 打开点歌台默认停在「歌名」大类，**光标落在字母 M 上**
- 歌曲行四种状态：未选中（深底）/ 选中（亮红底+白描边+歌名放大）/ 已点（行号变绿+「✓ 已点」）/ 正在播放（歌名金色●+「● 演唱中」）
- **修复重叠**：进点歌台时顶部「正在播放」信息条和右上小二维码自动隐藏，返回播放页再出现
- **修复双层菜单**：删掉常驻底部控制条，操作按钮只剩 ↓ 键呼出的一组（再按 ↓ 或返回键收起，15 秒无操作自动收）
- **修复 OK 弹出系统播放圆盘**：禁用 ExoPlayer 自带控制器，按 OK 只暂停/继续，画面不再压暗
- 「已点」成为点歌台底部大类之一，可置顶/删除；播放页三道杠的已点面板保留
- 网页播放页同样修复：点歌台打开时歌曲信息条/控制条强制让位（鼠标移动也不会再盖上来）

手机 H5 不显示二维码与快捷键说明（竖屏布局，本就没有这些元素），无需改动。

## 零、本版（v1.1.0）改了什么

按你提的 15 条意见逐条落地，**除第 15 条（把转码搬到投影仪）技术上不可行、已在文末第六节说明外，其余 14 条全部实现**。

| # | 你的意见 | 本版做法 |
|---|---|---|
| 1 | 后台加选框，筛选后批量删除/加列表/收藏 | 歌曲表首列**复选框**，勾选后浮出批量条：加入收藏 / 取消收藏 / 加入已点 / 打乱后加入 / 停用 / 启用 / **从曲库移除**。先筛「周杰伦」→ 全选 → 加入收藏，一步搞定 |
| 2 | 删除管理员口令 | **已彻底删除**（后端校验、前端输入框、localStorage 全部清掉），打开后台即用 |
| 3 | 恢复 IP 跳转链接 | 手机端底部、投影仪待机页、网页播放页、后台右上角都放了 `http://IP:9188` 的**可点链接**（手机点歌台 / 后台 / 投影仪页），电脑上可互跳 |
| 4 | 收藏爱心颜色不对 | 不再靠 emoji 颜色。**投影仪**改成按钮底色+文案（`❤ 已收藏` / `♡ 收藏`），**网页**加 `fav-on` 高亮类，三端全部以服务端 `favIds` 为准并随 SSE 实时刷新 |
| 5 | 「已点」侧栏关不掉 | 重写显隐逻辑：侧栏右上角 **✕**、**点面板外任意处**、**按 ESC**、再点一次「已点」按钮，四种方式都能关 |
| 6 | 网页暂停 2 秒自动续播 | 根因是播放器每 2.5 秒上报一次「正在播放」，把服务端的暂停状态顶回去了。现在**上报不再带暂停状态**，且本地操作后有 3 秒保护期不被服务端回写覆盖 |
| 7 | 点歌/已点界面缺置顶与打乱 | 三端补齐：手机（已点页 🔀 打乱、每条 ⬆ 置顶）、投影仪（已点面板 打乱/清空、每条 ⬆/✕）、网页播放页（同左），后台批量里也有「打乱后加入」 |
| 8 | 重做投影仪遥控器 | 见下方**第三节 · 遥控器键位表**，按你的定义逐键实现 |
| 9 | 默认禁止重复点歌 + 已点按钮变色 | `noRepeat` **默认开启**（可在后台关闭）。已点按钮变**绿底「✓ 已点」**，演唱中变**金底「● 演唱中」**，手机与投影仪即时同步 |
| 10 | 投影仪选中/未选中区别不明显 | 所有按钮改为焦点时**整块换红底 + 白描边 + 放大 1.06 倍**；已点/收藏用不同底色区分状态，不再只靠一条细边 |
| 11 | 已点的歌即刻后台读音轨 | 新增**预热**：歌曲一进队列就在后台按顺序探测音轨、备好兼容流，进度显示在**已点栏**（「读取音轨中 XX%」），前台只在这一首还没读完时提示 |
| 12 | 网页播放页没有回首页点歌按钮 | 新增 **「🎵 点歌台」** 按钮，页内直接嵌手机点歌台（不跳转、不打断播放），另有 ✕ 一键返回播放页 |
| 13 | 切歌/唱完是否延续原唱伴唱 | 已修正为**延续**。服务端记的是「角色」（原唱/伴唱）而不是音轨号，每首歌按自己的音轨映射去对应，切歌、自动接下一首都保持你选的角色 |
| 14 | 后台看不到收藏列表 | 新增 **「收藏夹」页签**：查看全部收藏、单条「点歌/取消收藏」、全部加入已点、打乱后加入、清空收藏；手机与投影仪的收藏页也补齐了打乱与置顶 |
| 15 | 转码能否挪到投影仪端 | 不可行，原因见第六节（当前已是「视频零转码」，NAS 只做 `${-c:v copy}` 的封装搬运） |

其余体验性改动：

- 扫描健壮性：网盘目录偶发读取不全时**不再误删曲库**（有阈值判断 + 文件二次确认），从曲库移除的歌记进黑名单、扫描时跳过、可一键恢复
- 首页/播放页都显示当前 `IP:端口`，配错地址时一眼看出

## 一、NAS 端：安装 fpk（必做，最先装）

### 1. 传输安装包

把 `fpk/ktv_1.2.0_x86.fpk`（约 100MB）拷到 NAS：
- 方法 A：飞牛网页文件管理器直接上传到任意目录（如 `/vol1/1000/`）
- 方法 B：SMB 共享复制过去

### 2. 安装 / 升级

1. 飞牛桌面 → **应用中心** → 右上角菜单 → **手动安装** → 选择 `ktv_1.2.0_x86.fpk`
2. 如果提示"手动安装被禁用"：SSH 登录 NAS 执行 `appcenter-cli manual-install enable` 后重试
3. 安装完成后应用列表出现 **家庭KTV**，状态应为「运行中」

> **从 v1.0/v2.x 升级**：直接覆盖安装即可。曲库索引、点唱记录、收藏、歌手头像都在 `/vol1/@appdata/ktv/`，不会被覆盖；配置会自动迁移到新版本（禁止重复点歌、预热默认打开，管理口令自动去除）。

命令行方式（可选）：

```bash
appcenter-cli install-fpk /vol1/1000/ktv_1.2.0_x86.fpk
appcenter-cli start ktv
appcenter-cli status ktv
```

### 3. 安装后自动完成的事

- 服务监听 `0.0.0.0:9188`（Node 22 + ffmpeg 静态运行时已内置，NAS 无需装任何环境）
- 默认曲库目录已预填：`/vol1/1000/ktv歌库`
- 首次启动自动开始后台扫描（只解析文件名，5000+ 首约几分钟；扫描期间已入库的歌可正常点唱）

### 4. 验证

浏览器打开 `http://192.168.1.100:9188/` 能看到欢迎页即成功。

| 用途 | 地址 |
|---|---|
| 手机点歌台 | `http://192.168.1.100:9188/m/` |
| 后台管理 | `http://192.168.1.100:9188/admin/` |
| 投影仪播放页（APK 的备用方案 / 电脑上试看） | `http://192.168.1.100:9188/play/` |

> 这三个地址在手机端底部、投影仪待机页、网页播放页里都是**可点的链接**，电脑上开着后台想切到投影仪画面，点一下就行。

### 5. 数据与日志位置

| 内容 | 路径 |
|---|---|
| 曲库索引（SQLite）、配置、歌手头像 | `/vol1/@appdata/ktv/` |
| 兼容处理缓存（MP2→AAC 的流） | `/vol1/@appdata/ktv/cache/` |
| 运行日志 | `/vol1/@appdata/ktv/ktv.log` |
| 点唱记录 / 收藏 / 移除黑名单 | 同数据库，卸载重装保留 |

**升级说明**：从旧版覆盖安装后，若之前已有曲库，歌星列表会自动补建，不用重扫。

## 二、后台管理

打开 `http://192.168.1.100:9188/admin/`。**已取消管理口令**，打开即用。

五个页签：`歌曲管理` / `歌手管理` / `收藏夹` / `批量导入` / `系统设置`。

### 1. 歌曲管理（含批量操作）

- 顶部搜索（歌名/歌手/拼音），右侧按 **语种 / 类型 / 状态 / 只看已收藏** 筛选，歌名下方有 A-Z 字母条
- **每行首列有复选框**。勾选任意一首后，表格上方浮出批量条：

| 按钮 | 作用 |
|---|---|
| ❤️ 加入收藏 | 把这批歌一次性加进收藏歌单 |
| 取消收藏 | 批量取消 |
| ➕ 加入已点 | 按当前顺序追加到待播队列（相当于替你点了一堆歌） |
| 🔀 打乱后加入 | 同上，但先随机打乱顺序 |
| 停用 / 启用 | 保留记录但不让点，适合片子坏了、音轨不对的歌 |
| 从曲库移除 | **只删索引，不动 NAS 上的视频文件**，可在设置页一键恢复 |
| 取消选择 | 清空勾选 |

表头复选框 = 全选当前筛选结果。典型用法：搜「周杰伦」→ 点表头全选 → 点「❤️ 加入收藏」，整个歌手的歌就进收藏夹了。

单行还有：**试播**（浏览器直接放）、**编辑**（改歌名/歌手/语种/类型）、**原唱↔伴唱对调**、查看点唱次数。

> 数量保护：一次批量最多 2000 首，超出会提示分批；移除操作会二次确认。

### 2. 歌手管理

- 自动聚合曲库里的所有歌手（`A & B` 合唱会分别列出）
- **上传头像**（jpg/png，建议正方形，显示在手机/投影仪的歌手墙）
- 设置 **地区**（内地/港台/欧美/日韩…）与 **性别**，手机端可据此筛选
- 顶部 A-Z 索引 + 搜索

### 3. 收藏夹（v1.1 新增）

- 列出所有收藏歌曲，与手机端、投影仪端是**同一份数据**（这里取消收藏，客厅屏幕同步消失）
- 顶部：**全部加入已点**、**🔀 打乱后加入**、**清空收藏**
- 每行：**点歌**、**取消收藏**

### 4. 批量导入（扫描曲库）

1. 确认曲库目录（可加多个，本地盘 + 网盘混用，本地优先）
2. 选择 **命名方式**：`歌手-歌名-语种-类型`（默认，你的曲库就是这种）
3. 点「开始导入」。过程中**实时显示正在处理的文件名**、已处理数量与进度条
4. 默认 **快速扫描**（不读音轨）。网盘环境不要开深度扫描

> 重复导入是安全的：按 mtime 判断，没变就跳过；点唱次数、收藏、音轨映射、移除黑名单都不会被覆盖。
>
> 网盘偶发读取不全时，服务不会把整个曲库当成"已删除"清空，只会跳过本次未列出的文件（日志里会有 `[scan] ⚠️` 提示）。

### 5. 系统设置

| 项 | 默认 | 说明 |
|---|---|---|
| 房间名 | 客厅 | 投影仪待机页与手机顶部显示的名字 |
| 开机/空闲自动播放 | 关闭 | `关闭` / `随机歌曲` / `收藏歌单`。没有待播歌曲时自动续播 |
| 禁止重复点歌 | **开启** | 同一首不能重复进待播队列（正在唱的那首不会被踢掉） |
| 点歌即后台预热 | **开启** | 歌一进"已点"就在后台按顺序探测音轨 / 备好兼容流，进度显示在已点栏。网盘带宽紧张时可关 |
| 原唱 / 伴唱音轨号 | 0 / 1 | 个别片子反了，在歌曲管理里单曲对调 |
| 播放兼容处理 | **开启** | MP2 音轨在设备上解不了时，首次点唱自动换封装（视频不动，只转音频） |
| 恢复被移除的歌曲 | — | 把「从曲库移除」的歌一次性恢复，之后重扫即回来 |
| 清理兼容缓存 | — | 释放 `/vol1/@appdata/ktv/cache/` |

底部还显示：歌曲总数 / 歌手总数 / 收藏数量 / 缓存数量。

## 三、投影仪端：安装 KTV Player APK

1. 把 `apk/HomeKTV-debug.apk` 拷到 U 盘 → 插投影仪 → 文件管理器安装
   （若提示"禁止安装未知来源"，到 设置 → 安全 里允许一次）
2. 打开 App，**默认已填好 `http://192.168.1.100:9188`**，直接点「连接」即可（地址不同再改）

### 遥控器键位表（v1.2.0 现行）

播放页（正在唱歌时）：

| 按键 | 单击 | 双击 | 长按 |
|---|---|---|---|
| **OK / 确认** | 暂停 / 继续 | — | — |
| **←** | 不动作（防误触） | **重唱** | **×2 速快退**，松开即停 |
| **→** | 不动作（防误触） | **切歌** | **×2 速快进**，松开即停 |
| **↑** | **切换原唱 / 伴唱** | — | — |
| **↓** | 呼出 / 收起**操作菜单**（暂停·切歌·重唱·音轨·快退·快进·收藏·点歌台） | — | — |
| **功能键（MENU/三道杠）/ 设置键** | **显示 / 隐藏已点面板** | — | — |
| **返回键（一次）** | 回到**点歌首页**（歌继续唱，不断） | — | — |
| **返回键（再一次）** | 回到**播放页** | — | — |
| **播放/暂停媒体键** | 暂停 / 继续 | — | — |
| **下一曲媒体键** | 切歌 | — | — |

> 快退/快进按住每 250ms 走 500ms（正好 ×2 速）；双击判定窗口 600ms。
> 播放页**不显示**二维码和快捷键说明，画面完整；二维码在待机页和点歌台右栏。

点歌首页（点歌台）：

- 底部大类：`歌名` / `歌星` / `排行` / `收藏` / `已点`，**功能键依次切换大类**
- **字母索引**在中间栏：A-E / F-J / K-O / P-T / U-Y / Z / 0-9 / 全，每行 5 个大按钮；OK 选中字母即筛选
- 歌曲列表在左栏：光标默认落在第一行的**「点歌」**按钮上，**向左一步=「♥ 收藏」**（OK 收藏），向右一步=字母索引
- **已点按钮变绿底「✓ 已点」**，正在唱的变金底「● 演唱中」——一眼看出哪些点过了
- `已点` 大类：每条 **⬆ 置顶** / **✕ 删除**；播放页功能键的已点面板同样可用，还会显示**后台读音轨进度**
- 右栏：点歌二维码 + 快捷键说明；点歌台整体半透明，正在唱的画面能透出来

### 界面与状态

- 所有按钮**焦点态 = 整块红底 + 白描边 + 放大**，遥控器走到哪一目了然
- 收藏按钮：`❤ 已收藏`（高亮底色）/ `♡ 收藏`（普通底色）
- 待机页：大字房间名 + 点歌二维码 + `http://IP:9188` 可点链接（点歌台 / 后台） + 设置入口

### 设置

待机页 → 设置：服务器地址、开机/空闲自动播放（关 / 随机 / 收藏歌单）。

## 四、手机端：微信扫码点歌

1. 投影仪待机/播放页显示二维码（指向 `http://192.168.1.100:9188/m/`）
2. 微信「扫一扫」→ 输入昵称 → 开始点歌

功能（底部五个大类：**歌名 / 歌星 / 预览 / 收藏 / 已点**）：

- **顶部正在播放条**：歌名/歌手、进度、❤ 收藏、切原唱伴唱、切歌
- **搜索**：中文、拼音全拼、拼音首字母都行；**歌名大类只搜歌名**（歌手请用「歌星」大类）
- **分类筛选**：语种、类型、排序（默认/热门/最新）、只看已收藏（无字母条，打字筛选更方便）
- **歌星页**：地区 + 性别 + 头像墙
- **预览**：实时显示投影仪正在播的画面（静音），点「⛶ 全屏横屏」全屏观看并出声；mpg 片源手机解不了会提示
- **收藏页**：一键收藏、筛选框、`全部点唱`、**🔀 打乱**、随机唱一首
- **已点页**：筛选框、每条 **⬆ 置顶** / **✕ 删除**，顶部 **🔀 打乱** / 清空，条目上显示**读音轨进度**
- 已点的歌按钮变成**绿底「✓ 已点」**，重复点会被拦下（默认禁止重复）
- 底部有 `服务地址 http://IP:9188` 和「后台管理 / 投影仪页」链接，手机上也能直接跳

> 微信内打开异常时：长按二维码 → 识别，或复制链接到系统浏览器，功能一致。
> 建议：路由器里给 NAS 绑定静态 IP（DHCP 保留），否则 IP 变了二维码就失效。

## 六、片源格式说明（MP2 音频 / 为什么不能把处理挪到投影仪）

你的曲库两种格式：

| 格式 | 视频编码 | 音频编码 | 投影仪 APK | 电脑/手机浏览器 |
|---|---|---|---|---|
| `.mkv` | H.264 | MP2 ×2 | 首次点唱时换封装（视频原样复制 + 音频转 AAC），之后秒开 | 同左 |
| `.mpg` | MPEG-2 | MP2 ×2 | 首次点唱时封装成 MPEG-TS（视频原样复制 + 音频转 AAC） | **浏览器不支持 MPEG-2 视频**，会提示改用投影仪 |

**关于第 15 条「把解码/转码/读音轨都放到投影仪端，NAS 只做存储」——技术上做不到，原因如下：**

1. **MP2 是投影仪也解不了的格式**。KTV 老片源的音频是 MPEG-1 Layer II，Android 的 MediaCodec 和 ExoPlayer 软解链里都没有 MP2 解码器。如果 NAS 只做文件服务器，投影仪拿到 mkv 会直接 `DECODER_INIT_FAILED`——这正是你在 v2 之前遇到的报错。要在投影仪端解决，就得让 APK 自己做转码，而那需要把 ffmpeg 塞进 APK 并用 CPU 实时软编 AAC，J1900 都吃力的活让投影仪那颗芯片实时扛，必然掉帧。
2. **浏览器更不可能**。手机/电脑网页播放页是 `<video>` 标签，浏览器既不解 mkv 双音轨也不解 MP2，服务端必须给出一个浏览器认的流。
3. **当前方案已经是"最小开销"**：视频 `-c:v copy` 逐帧原样复制（已用校验和验证零转码），只把音频换成 AAC、换个封装。一个 4 分钟片源在 NAS 上几秒钟完成，结果缓存在 `/vol1/@appdata/ktv/cache/`，同一首永远只做一次。
4. **而且这件事你现在基本感觉不到**：v1.1 的「点歌即后台预热」会在歌进队列的第一时间按顺序把这些活干完，等上一首唱完，下一首已经就绪，切歌零等待。

所以 NAS 的定位是「存储 + 轻量封装搬运 + 状态中枢」，不是"转码服务器"——CPU 只在**每首歌第一次被点**时动几秒，之后完全不动。

后台「系统设置 → 播放兼容处理」控制这个行为，**建议保持开启**。关掉后：能直接解的片源照常播，解不了的会明确报错而不是黑屏。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 应用中心显示「未运行」 | SSH 执行 `/var/apps/ktv/target/../cmd/main status`；看日志 `tail -50 /vol1/@appdata/ktv/ktv.log` |
| 9188 端口被占 | 改 `data/config.json` 的 port 后在应用中心重启应用 |
| 扫描到 0 首 | 后台确认目录路径；SSH 执行 `ls /vol1/1000/ktv歌库` 验证挂载正常。日志出现 `[scan] ⚠️` 说明本次目录读取不全，已自动保护，重扫即可 |
| 扫描很快但歌手是空的 | 老库升级场景：重启一次应用会自动补建歌手 |
| 导入很久没动静 | 看批量导入页的「当前处理」；网盘首次列目录慢是正常的 |
| 切伴唱没反应 | 该片源可能只有一条音轨，或音轨标题不是「原唱/伴唱」。在歌曲管理里手动指定音轨号 |
| 切歌后伴唱变回原唱 | 不应该再出现（v1.1 记的是"角色"而非音轨号）；若仍有，看日志确认该首 `trackCount` 是否 ≥2 |
| 点了歌但提示「已点过」 | 默认禁止重复点歌；后台系统设置里可关闭 |
| 已点按钮不变色 | 手机/投影仪都靠 SSE 推送刷新；确认页面还在前台、没断网（页面顶部会显示连接状态） |
| 网页暂停后又自己播 | 已修（v1.1）。若仍出现，确认浏览器没装"自动播放拦截"类插件 |
| 投影仪播某首报「播放失败」 | 返回键跳过（自动切下一首），OK 键重试；日志看具体原因 |
| 第一次点某首歌要等十几秒 | 正常（换封装 + 网盘读文件），同一首只等一次；开启「点歌即后台预热」后基本感知不到 |
| 防火墙开着无法访问 | 飞牛 设置 → 安全性 → 防火墙，放行 TCP 9188 |
| 微信扫码提示非官方页面 | 继续访问即可（局域网 http 无证书）；或改用系统浏览器 |
| 播放卡顿 | 115 网盘串流带宽问题。把常唱的歌拷到 NAS 本地盘，曲库目录里加一条本地路径并置顶 |
